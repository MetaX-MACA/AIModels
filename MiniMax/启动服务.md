## 启动步骤

**PD 分离部署时，Prefill 实例与 Decode 实例需遵循特定的配比规则。为便于后续说明，PD 分离配比采用以下格式表示：**

`xPm yDn`：表示 x 个 Prefill 实例（每个实例占用 m 个节点）和 y 个 Decode 实例（每个实例占用 n 个节点）。每个节点默认配置 8 张GPU。

启动步骤分三个部分：

- 启动Prefill实例
- 启动Decode实例
- 启动MiniLB实例

### 部署环境示例

**1P2 1D4 是指使用 1 组 Prefill 实例（每组 2 个节点）和 1 组 Decode 实例（每组 4 个节点）的部署方案。以1P2 1D4为例进行部署说明。**

假设当前共有 6 个节点，IP 地址分配如下：

| 节点   | IP 地址       | 用途                   |
| ------ | ------------- | ---------------------- |
| 节点 1 | `192.168.0.1` | Prefill 节点（Rank 0） |
| 节点 2 | `192.168.0.2` | Prefill 节点（Rank 1） |
| 节点 3 | `192.168.0.3` | Decode 节点（Rank 0）  |
| 节点 4 | `192.168.0.4` | Decode 节点（Rank 1）  |
| 节点 5 | `192.168.0.5` | Decode 节点（Rank 2）  |
| 节点 6 | `192.168.0.6` | Decode 节点（Rank 3）  |

**其中，节点 1-2 用于部署 Prefill 实例，节点 3-6 用于部署 Decode 实例。**

### 启动 Prefill 实例

**以下操作均在容器中文件夹目录`/workspace/llm-launch`下进行。**

使用 `./sglang/prefill.sh` 脚本启动 Prefill 实例。

**在多实例多节点部署场景中，需指定每个实例主节点（Rank 0）。当前实例数量为1，节点数量为2，主节点 Rank 0 节点的 IP 地址为 `192.168.0.1`。**

**步骤 1：在 Rank 0 节点容器中执行**

```shell
./sglang/prefill.sh \
	minimax-m2.sh \
    192.168.0.1 \
    2 \
    0
```

**参数说明**

- 启动Prefill实例脚本
- 模型名称：参考[配置模型文件](启动准备.md#配置模型文件)
- 每个实例主节点IP
- 当前实例节点总数
- 当前节点排序，从0开始(Rank 0)

**步骤 2：在 Rank 1 节点容器中执行**

```shell
cd <容器中脚本目录>
./sglang/prefill.sh \
	minimax-m2.sh \
    192.168.0.1 \
    2 \
    1
```

> **注意**：Rank 1 启动无需等待 Rank 0 启动完成。

**步骤 3：验证实例启动**

等待 Rank 0 节点的终端打印以下信息，表明 Prefill 实例已成功启动：

```
The server is fired up and ready to roll!
```

> **注意**：上述示例以 2 个节点为例。若实际部署的节点数量不同，请相应调整命令中的"节点总数"参数，并在每个节点上执行对应的命令（Rank 从 0 开始递增）。

### 启动 Decode 实例

**以下操作均在容器中文件夹目录`/workspace/llm-launch`下进行。**

使用 `./sglang/decode.sh` 脚本启动 Decode 实例。

**在多实例多节点部署场景中，需指定每个实例主节点（Rank 0）。当前实例数量为1，节点数量为4，主节点 Rank 0 节点的 IP 地址为 `192.168.0.3`。**

**在 Rank 0 节点容器中执行**

```shell
./sglang/decode.sh \
	minimax-m2.sh \
    192.168.0.3 \
    4 \
    0
```

**参数说明**

- 启动Decode实例脚本
- 模型名称：参考[配置模型文件](启动准备.md#配置模型文件)
- 每个实例主节点IP
- 当前实例节点总数
- 当前节点排序，从0开始(Rank 0)
> **注意**：上述示例以 4 个节点为例。若实际部署的节点数量不同，请相应调整命令中的"节点总数"参数，并在每个节点上执行对应的命令（Rank 从 0 开始递增）。

**各节点容器中执行命令如下**

| Rank | 命令                                               |
| ---- | -------------------------------------------------- |
| 0    | `./sglang/decode.sh minimax-m2.sh 192.168.0.3 4 0` |
| 1    | `./sglang/decode.sh minimax-m2.sh 192.168.0.3 4 1` |
| 2    | `./sglang/decode.sh minimax-m2.sh 192.168.0.3 4 2` |
| 3    | `./sglang/decode.sh minimax-m2.sh 192.168.0.3 4 3` |


等待 Rank 0 节点的终端打印以下信息，表明 Decode 实例已成功启动：

```
The server is fired up and ready to roll!
```

### 启动 MiniLB 实例

**以下操作均在容器中文件夹目录`/workspace/llm-launch`下进行。**

使用 `./sglang/minilb.sh` 脚本启动 MiniLB 实例。MiniLB 负责在 Prefill 和 Decode 实例之间进行负载均衡调度，该脚本可在任意节点的容器中执行。**建议等待 Prefill 和 Decode 实例全部启动后再启动 MiniLB实例。**

**在任意节点容器中执行**

```shell
./sglang/minilb.sh \
	prefill 192.168.0.1 \
	decode 192.168.0.3
```

**参数说明**

- 启动MiniLB 实例脚本
- 每个Prefill实例主节点IP，每个IP空格隔开
- 每个Decode实例主节点IP，每个IP空格隔开

**当 Prefill 和 Decode 各自只有 1 个 Rank 0 时。如果在 192.168.0.1 启动 MiniLB，当终端打印以下信息，表明 Prefill 和 Decode 实例均已准备就绪：**

```
INFO:     Started server process [972879]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://192.168.0.1:8001 (Press CTRL+C to quit)
```

> **注意**：上述示例中的 IP 地址需替换为实际的 Prefill 和 Decode实例主节点IP。
