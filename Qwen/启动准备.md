### 容器启动

**镜像成功获取后，参考以下命令启动容器**

```shell
docker run -itd \
	--privileged \
	--network=host \
	--ipc=host \
	--security-opt seccomp=unconfined \
	--security-opt apparmor=unconfined \
	--ulimit memlock=-1 \
	--name qwen-1-p-1 \
	-v /home/models/:/home/models/ \
	cr.metax-tech.com/public-init/maca/sglang:v0.5.7-qwen3.5-rc2-maca.ai.3.0.1032.20260227-torch2.8-py310-ubuntu22.04-amd64 \
	bash
```

**参数说明**

| 名称 | 详细说明 |
|----|------|
| `-itd` | 可与容器进行交互，容器后台运行 |
| `--privileged` | 特权模式，允许容器内访问宿主机设备 |
| `--network=host` | 容器内网络模式与宿主机共享 |
| `--ipc=host` | 容器内与宿主机共享内存通信 |
| `--security-opt seccomp=unconfined` | 关闭 seccomp安全策略限制 |
| `--security-opt apparmor=unconfined` | 关闭 AppArmor安全策略限制 |
| `--ulimit memlock=-1` | 容器内与宿主机内存限制保持一致 |
| `--name qwen-1-p-1` | 容器名称，容器名称规范参考\[模型名称\]-\[P/D实例序号\]-\[p/d\]-\[P/D节点序号\]，参考[PD分离配置说明](../../README.md#PD分离配置说明) |
| `-v /home/models/:/home/models/` | 模型权重挂载路径，前面为宿主机路径，后面为容器内路径。请按照实际修改 |
| `cr.metax-tech.com/public-init/maca/sglang:v0.5.7-qwen3.5-rc2-maca.ai.3.0.1032.20260227-torch2.8-py310-ubuntu22.04-amd64` | 获取镜像名称，请按照实际修改 |
| `bash` | 容器启动后执行`bash`命令 |

##### 区分网卡用途

剔除所有非 Active 状态的网卡后，6 张Mellanox网卡的状态汇总如下：

| 设备名称    | 设备型号 | 状态   | 速率 | IP           |
| ----------- | -------- | ------ | ---- | ------------ |
| mlx5_bond_0 | MT4127   | Active | 25   | 192.168.0.1  |
| mlx5_bond_1 | MT4125   | Active | 100  | 192.4.0.23   |
| mlx5_bond_2 | MT4129   | Active | 200  | 192.4.128.29 |
| mlx5_bond_3 | MT4129   | Active | 200  | 192.4.129.2  |
| mlx5_bond_4 | MT4129   | Active | 200  | 192.4.130.9  |
| mlx5_bond_5 | MT4129   | Active | 200  | 192.4.131.15 |

**Mellanox网卡用途判断原则**：

1. **业务网卡**：速率一般为10/25G，其分配的 IP 通常为 ssh 登录节点时使用的 IP。
2. **存储网卡**：速率一般介于计算网卡和业务网卡之间，一般为100/200G，同时网段与计算网卡差异较大。
3. **计算网卡**：速率通常为 200/400 G，并且多张计算网卡的网段接近。

**本示例分析**：

- `mlx5_bond_0`：速率25G，且该网卡分配到的 IP 为当前节点 IP，判定为**业务网卡**。
- `mlx5_bond_1`：速率100G，且网段差异较大，判定为**存储网卡**。
- `mlx5_bond_2` 至 `mlx5_bond_5`：速率200G，且四张网卡网段接近，判定为**计算网卡**。

> **注意**：并非所有节点都会配置存储网卡。如果当前节点未配置存储网卡，其功能将由计算网卡承担。这不影响部署成功，但会对性能造成一定影响。

#### TCP 网络测试

SGLang 在运行过程中会使用 ZMQ 进行进程间握手和数据传输，因此需要验证基础 TCP 通信网络的稳定性，避免因丢包或延迟过高而影响推理性能。

##### 测试方法（基于 iperf3）

| 角色 | 命令 |
|----|----|
| 服务端（Server） | `iperf3 -s -p $PORT` |
| 客户端（Client） | `iperf3 -c $SERVER_IP -p $PORT -t 600 -i 10` |

##### 测试前准备

执行以下命令安装 `iperf3` 工具：

```shell
apt update
apt install -y iperf3
```

请确保**所有参与测试的节点**均已安装 `iperf3` 工具。

##### 批量测试

以下脚本用于批量测试多节点之间的 TCP 通信性能。当前示例包括 6 个节点，其中 4 个节点作为客户端，2 个节点作为服务端（s1 和 s2）。请根据实际部署环境修改脚本中的 IP 地址。

假设 6 个节点的 IP 地址如下：

```shell
# 客户端节点
192.168.0.1
192.168.0.2
192.168.0.3
192.168.0.4
# 服务端节点
192.168.0.5
192.168.0.6
```

**步骤 1：在服务端启动 iperf3**

在两个服务端节点上分别执行：

```shell
iperf3 -s -p 5555
```

**步骤 2：客户端测试脚本**

```shell
s1="192.168.0.5" # 服务端节点 IP
s2="192.168.0.6" # 服务端节点 IP
c1="$1" # 客户端节点 IP，通过参数传入
{ echo $c1 $s1; iperf3 -c $s1 -p 5555 -t 600 -i 0 | sed -n '/sender/,/receiver/ p'; } | xargs &
{ echo $c1 $s2; iperf3 -c $s2 -p 5555 -t 600 -i 0 | sed -n '/sender/,/receiver/ p'; } | xargs
wait
```

参数说明：

#### 容器中MCCL 双机测试

MCCL 是支持多机多卡通信的集合通信库，用于跨节点的 GPU 间数据交换。在涉及多机多卡协同推理的场景下，提前验证 MCCL 的双机通信能力可避免部署后出现通信故障。

**测试环境示例**

| 节点 | IP 地址 | 角色 |
|----|-------|----|
| 节点 A | `192.168.0.1` | 测试节点 |
| 节点 B | `192.168.0.2` | 测试节点 |

> **注意**：MCCL 双机测试需要两个节点的容器之间能够双向通信，因此需要配置**双向免密登录**（A→B 和 B→A）。

##### 配置 ssh 免密登录

为实现双机之间的无密码访问，需要在节点间配置 ssh 免密登录。

**步骤 1：在节点 B 上安装 ssh 服务**

进入节点 B 的容器，执行以下命令安装 OpenSSH 服务端和客户端：

```shell
apt update
apt install openssh-server openssh-client
```

**步骤 2：重置 Docker root 用户密码**

设置节点 B 容器的 root 用户密码：

```shell
passwd root
```

**步骤 3：配置 ssh 服务**

编辑节点 B 容器的 `/etc/ssh/sshd_config` 文件，确保以下配置项正确设置：

```
Port 11022
PermitRootLogin yes
```

参数说明：

- `Port`：ssh 服务监听端口，可根据实际环境自行配置（**需确保防火墙允许该端口**）
- `PermitRootLogin yes`：允许 root 用户通过 ssh 登录

**步骤 4：重启 ssh 服务**

在节点 B 容器上重启 ssh 服务使配置生效：

```shell
service ssh restart
```

**步骤 5：配置免密登录（A → B）**

进入节点 A 的容器，执行以下命令生成 ssh 密钥并将公钥复制到节点 B：

```shell
ssh-keygen -t rsa
ssh-copy-id -p 11022 root@192.168.0.2
```

**步骤 6：验证免密登录（A → B）**

在节点 A 执行以下命令，验证能否无需密码登录到节点 B：

```shell
ssh root@192.168.0.2 -p 11022
```

若成功登录且无需输入密码，则说明 A→B 的免密登录配置成功。

**步骤 7：配置双向免密登录（B → A）**

按照上述步骤 1 至 6 的相同流程，在节点 A 上配置 ssh 服务，并从节点 B 配置免密登录到节点 A，实现双向免密访问。

##### 执行 MCCL 双机测试

完成 ssh 免密配置后，即可执行 MCCL 双机通信测试。

**测试脚本**：

将以下脚本保存为 `mccl_test.sh`，并根据实际环境修改相关参数后执行。

```shell

      -mca btl_tcp_if_include ${IP_MASK} -mca oob_tcp_if_include ${IP_MASK}"
```

**参数说明**：

| 参数 | 说明 |
|----|----|
| `OMPI_MCA_plm_rsh_args` | OpenMPI 的 RSH 参数，指定 ssh 端口和跳过主机密钥检查。 |

| `SOCKET_NIC` | 双机各自用于 socket 通信的网络接口名称。如果双机的接口不同，每个接口可用逗号隔开，例如 `enP3s48f0,enP3s48f1`。 |

| `MPI_ENV` | MPI 相关参数，排除 UCX/OpenIB 等可能冲突的组件 |
| `-b 1K -e 1G -f 2` | 测试消息大小范围：从 1KB 到 1GB，按 2 倍递增 |

> **注意**：`CARD_NUM`、`HOST_IP`、`IP_MASK`、`IB_PORT` 和 `SOCKET_NIC` 需按照实际情况进行修改。
